# SO-101 Reconstruction Operating Rules

- Treat `docs/reconstruction/CURRENT_STATE.json` and the local project-state
  file created in this repository as distinct: inherited evidence is immutable
  history, while new authority must be composed locally.
- Preserve fixture, synthetic, simulation, replay, learned-policy, physical
  read-only, and physical task evidence as separate proof classes.
- Never treat shell permissions, copied permits, or a component artifact as
  training, hardware, physical-transfer, or promotion authority.
- Use pinned LeRobot behavior directly. Own only coordinates, task semantics,
  evidence identity, authority composition, bounded runners, and handoffs.
- Keep held-out episodes out of training and training statistics.
- Report chunk-50 and receding-10 separately, with exact queue reset and tail
  accounting.
- Before any one-use run, bind the source commit, dependencies, inputs, output
  absence, active owner window, and enough uninterrupted completion time.
- No automatic retries, second replacements, threshold changes, external
  compute, Brev, hardware access, or destructive operations.
- Commit scoped paths and keep generated datasets, checkpoints, outputs,
  credentials, caches, and private observations out of Git.

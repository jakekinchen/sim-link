# Proposed Task T17.5b - Scripted Single-Cube Grasp Episode Generation

Status: adopted as pending task T17.5b at Brief 111 / Reviewer Decision 139
(2026-07-13). Its execution contract must be written and reviewed at the next
brief boundary. Nothing in this document grants authority; all authority
language defers to the active ledger.

## Why this task must exist

The ledger's `remaining` line names "real generated grasp episodes" but no
T-number owns them. T17.4 is verified over a source projection whose only two
frames are quarantined for exactly five reasons
(`configurations/robot_lab/experience_record_contract.json`
`fixture_projection/quarantine_reasons`):

1. `source_artifact_does_not_retain_per_frame_requested_proposed_projected_sent_measured_actions`
2. `source_artifact_does_not_retain_per_frame_requested_and_achieved_gripper_pose`
3. `source_artifact_does_not_retain_simulation_actuator_effort`
4. `hard_boundary_segments_and_unpadded_action_windows_not_compiled`
5. `normalization_and_preprocessing_bundle_not_compiled`

Reasons 1-3 are per-frame evidence gaps in the T19.0l proof artifact, which was
built to prove grasp feasibility, not to emit training records. Reasons 4-5 are
downstream compilations that already have owners (T17.4/T17.5, T17.3). This
task closes reasons 1-3 at the source by re-running the verified scripted
grasp as a *recording* expert. Without it, T17.7's 100-window replay audit,
T18.1 sampling, and T20.1's dataset freeze have no input and M17 closes over
an empty set.

## Adoption amendment - derived scripted actions

Brief 111 found that the current T17.4 and T17.5 implementations accept only
`observed` action variants. That is correctly fail-closed today, but it is
incompatible with this task's truthful representation of a scripted expert:
by-construction-identical variants must remain `derived` with a named
derivation rather than be relabeled as observed. Before generation, T17.5b
must add and test a narrow compatibility rule in both compilers: `derived` is
eligible only when it has a nonempty finite value vector plus explicit,
verifiable derivation provenance; all other availability states remain
quarantined or rejected. This amendment is required evidence work, not an
authority grant.

# Slice Brief NNN - T17.5b Scripted Grasp Episode Generation

**Date:** (assign)

## Objective

Re-run the verified T19.0l geometry-derived unilateral grasp as a recording
scripted expert over deterministically seeded single-cube scenes, emitting
immutable raw rollout and frame records that satisfy the T17.1 contract with
complete per-frame action evidence, so the verified T17.4 compiler produces
its first non-empty eligible frames and hard-boundary segments.

## Contract

- Bind to the current T17.1 experience-record contract identity, the T17.2
  canonical processor identity, and the T19.0l grasp proof identity recorded
  in `project_state.json` at brief start. Do not rewrite any of them.
- Control semantics per the T17.1 enums: `source_class: mujoco_expert`,
  `proof_mode: simulation_unassisted`, `control_mode: scripted_mujoco_expert`,
  `controller_owner: geometry_derived_mujoco_expert`. `recovery` remains a
  control mode and never a task phase.
- Every frame records all five action variants
  (`requested/proposed/projected/sent/measured`) over the six named joints,
  requested and achieved gripper pose, and simulation actuator effort, each
  wrapped as a sourced value with an explicit availability state. For a
  scripted MuJoCo expert no variant may be `not_observed`; a variant that is
  identical to another by construction (e.g. `proposed` = `requested` with no
  safety projector in the loop) is recorded as `derived` with its derivation
  named, never omitted.
- Every frame records `task_phase` from the T17.1 phase enum mapped from the
  expert's phase machine, `source_phase` verbatim, monotonic simulation
  timestamps, and the scene/prompt/coordinate provenance dictionaries.
  Privileged simulator state (reward, progress, future or privileged fields)
  is stored only under privileged roots, never in actor-visible observation
  paths.
- Per-frame observations retain the top and wrist 256px RGB renders encoded
  with the deterministic `grasp_evidence.encode_png_image` path, plus measured
  joint positions/velocities. Camera order and naming follow the T17.3 bundle
  binding.
- Hard-boundary events are declared explicitly per the T17.1 event enum:
  `rollout_start`, every `phase_change`, `scene_change` between episodes,
  `rollout_end`. Resets between episodes are `reset` boundaries. Unknown or
  ambiguous semantics fail closed into quarantine, never into inference.
- Scene randomization is bounded by the proven capability envelope: the single
  proven cube asset, planar position within the reachable band established by
  the T19.0 series, and yaw. Per-episode grasp poses are re-derived through
  the existing geometry-derived pipeline (grasp pose solver plus aperture
  inversion); no friction, compliance, or search-range tuning.
- Episode seeds are a fixed, committed list (recommended: 32 seeds, seed 0 =
  the exact verified T19.0l nominal pose). Episodes are recorded with honest
  outcomes: an episode whose strict-v2 gates fail is retained and labeled
  truthfully, not discarded or relabeled. Terminal outcome and strict success
  are distinct signed fields.
- Raw rollout bytes are append-only, content-addressed on local disk under a
  declared store root outside version control. The repository commits only
  the signed store manifest (per-episode and per-frame identities, byte
  hashes, seed list, generator/config identities, realized counts). Re-running
  the generator with the same seeds must reproduce a byte-identical manifest.
- Boundary separation per ledger rules: (a) generator feature commit,
  (b) generation-run commit (manifest plus artifacts), (c) compiler-run
  commit that binds the new store as a new T17.4-path compiled view in a new
  artifact directory - the verified T17.4 outputs and Brief 110 evidence are
  never rewritten.
- Explicit non-goals: no windows (T17.5 owns them), no normalization claims,
  no training, no optimizer, no Brev or paid compute, no hardware, no motion,
  no policy actions, no multi-object scenes, no relabeling.

## Verification

- Deterministic rerun: same seeds produce a byte-identical store manifest.
- Contract validation: every emitted rollout and frame passes
  `validate_raw_rollout_record` and `validate_frame_records` with zero
  availability downgrades on action variants, gripper pose, or effort.
- Compiled-view proof: the new T17.4-path run reports >0 eligible frames and
  >0 segments, with quarantine reasons 1-3 absent for all retained frames;
  segments never bridge declared hard boundaries (spot-verified per episode).
- Truthful counts: configured episodes, realized episodes, strict-v2 pass
  count, and per-gate failure counts (measured/threshold/signed margin) are
  reported without padding; seed 0 must pass the full strict-v2 cycle
  (8/8 hold, 24/24 lift, 12/12 unsupported hold, 24/24 lower) or the slice
  fails.
- Rendered keyframe evidence per the standing 3-5 frame requirement for at
  least seed 0 and every failing episode class.
- Focused unit tests plus the relevant broad gate, state-pointer `--check`,
  same-agent adversarial review, scoped commits, and remote confirmation all
  agree before T17.5b is marked verified. Ledger and `project_state.json`
  updated at start and at the verification boundary, followed by
  `python3 scripts/robot_lab/sync_project_state_pointers.py --apply`.
